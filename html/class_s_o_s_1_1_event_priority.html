Detailed Description

Defines canonical priority constants for deterministic execution ordering within the S.O.S. event bus (API).

Pipeline Execution Order: Event handlers are dispatched in ascending order of their numerical priority weight:

Priority TierWeight & Recommended Purpose
System-2.0 — Low-level lifecycle orchestration, window closing, and profile tearing down.
State-1.0 — Data store synchronization and model mutations before views react.
Default0.0 — Standard domain logic and general third-party mod event listeners.
UI1.0 — Primary GUI reconstruction, widget refreshes, and layout reflows.
PostUI2.0 — Post-render effects, animation sequence triggers, telemetry, and diagnostics.

Fractional In-Between Prioritization: Because priorities are represented as normalized double-precision floating-point numbers (rounded to 4 decimal places), developers can insert handlers between standard tiers (e.g., EventPriority.State + 0.5 for history navigation stacks, or EventPriority.UI - 0.1 for pre-render setup) without risking key collisions or precision drift in the underlying Red-Black tree.

// Subscribing a state mutator to run before the UI renders:
API.On<Prefab>(CommKeys.SelectTarget, prefab =>
{
UpdateDataModel(prefab);
}, EventPriority.State);
// Subscribing a UI panel that relies on the updated data model:
API.On<Prefab>(CommKeys.SelectTarget, prefab =>
{
RefreshCustomPanel(prefab);
}, EventPriority.UI);

◆ Default

const double SOS.EventPriority.Default = 0
static

Default priority tier (0.0). The neutral baseline tier for standard domain logic and general mod event handlers.

Used when no explicit priority order is specified in API.On(string, Action, double) or API.On<T>(string, Action<T>, double). Suitable for standard game logic that does not require specialized pre- or post-processing guarantees.

Post-UI priority tier (2.0). Dispatched after primary visual components have completed their layout and drawing passes.

Ideal for initiating visual transitions, triggering GUI.GUIAnimSequence animations, executing diagnostics, or logging telemetry where visual elements must already be present in the active hierarchy.

◆ State

const double SOS.EventPriority.State = -1
static

State priority tier (-1.0). Dispatched to synchronize configurations, caches, and data stores before visual components react.

Handlers at this level update data models, selected targets, and active configs. Guaranteed to execute before Default domain listeners and UI layout renderers.

◆ System

const double SOS.EventPriority.System = -2
static

System priority tier (-2.0). Dispatched first to handle critical infrastructure, lifecycle termination, and profile switching.

Handlers registered at this tier run before any data state mutations occur. Reserved primarily for internal controller cleanup and low-level system coordination.

◆ UI

const double SOS.EventPriority.UI = 1
static

UI priority tier (1.0). Dispatched to update, construct, or re-render graphical user interface components.

Handlers at this level are guaranteed to run after System and State handlers have fully committed their changes. Visual controls reading from the state store (such as API.GetState<T>(string)) will always receive freshly updated data.
